# SPEC: geiger-tube firmware — 乱数の管・第二源泉 (ESP32・USB版)

## 目的

CAJOE / RadiationD v1.1系ガイガーカウンターのパルス出力から崩壊イベントの
到着時刻を取得し、間隔からエントロピーを抽出して **USB シリアルに吐く**
常駐ファームウェア。吐いた粒の行き先(カーネルのエントロピープール / kuda の
`POST /ingest`)はホスト側の `tubed` が決める(`docs/tubed-spec.md`)。

ESP32 は「物理エントロピー源」に徹する。ネットワークにも秘密情報にも触らない。

```
[GM管パルス] → ESP32(このファーム) → USBシリアル → tubed → /dev/random
                                                          └→ kuda /ingest
```

## ハードウェア前提

- ボード: Freenove ESP32-WROOM-32E (Arduino framework / PlatformIO)
- 信号入力: GPIO 4 (基板のVIN=パルス出力。負論理、通常High→検出時Low)
- 給電: ホスト(Ubuntu)の USB ポートから。ガイガー基板へは 5V ピンから供給
- オンボードLED: パルス検出時に短く点滅(視覚確認用)
- ESP32-WROOM-32E に USB-OTG は無く、オンボードの USB-UART ブリッジ経由で
  接続する。ホストからは `/dev/ttyUSB0` 相当のシリアルとして見える

## 設定の分離 (必須)

`config.h` (gitignore対象) に以下を分離。`config.example.h` をリポジトリに置く:

- `GPIO_PULSE` (default 4) / `GPIO_LED` (default 2)
- `DEADTIME_US` / `WHITEN_EVENTS` / `BLOCK_QUEUE_MAX`
- `SERIAL_BAUD`
- `TEST_MODE` / `TEST_CPM`

**このファームは秘密情報を一切持たない。** WiFi 資格情報も INGEST_TOKEN も
存在しないため、ファームやシリアルログからトークンが漏れる経路が構造的に無い。

不揮発領域は NVS のネームスペース `tubelet` のキー `boots`(起動回数)だけを使う。
`boot_id` の元になるので、**NVS を消去すると boot_id が過去の値に戻る**。
その状態でホスト側の tubed を動かしたままだと、`(boot_id, seq)` が既出と一致して
新しい粒が `dup` として捨てられる。フルチップ消去をしたら tubed も再起動する。

## 処理パイプライン

1. **割り込み**: GPIO立ち下がりエッジでISR起動。ISRは micros() を
   リングバッファ(容量512イベント)に積むだけ。処理はループ側で行う。
2. **デッドタイム除去**: 前イベントから 300µs 未満のパルスは破棄
   (GM管のデッドタイム+チャタリング対策)。
3. **間隔計算**: 隣接イベントの到着間隔 Δt (µs, uint32) を得る。
4. **抽出**: Δt の下位8bitを収集バッファに追加。
5. **白色化**: 収集バッファが512イベント分(512バイト)溜まったら
   SHA-256でハッシュし、出力32バイトを未送出キューへ。
   → 32バイトに申告できるのは最大256bit。512イベントで256bit なので、
   計上は「1イベント=0.5bit」になり、量子化などで実質が目減りしていても
   過大申告になりにくい。
6. **出力**: キュー先頭から `E` 行としてシリアルに書く。UARTの送信余裕が
   無ければ書かずに保持し、次のループで再試行する。

## シリアルプロトコル (行指向テキスト・115200 8N1)

```
V tubelet <fw> boot=<hex8> mode=<geiger|test> whiten=<n> gpio=<n>
E <boot_id hex8> <seq> <events> <geiger|test> <base64 32B>
S cpm=23 events=1234 dead=5 blocks=12 queue=96B up=120s
W <message>
```

- `boot_id` は `SHA-256(MAC || NVSのブートカウンタ)` の先頭4バイト。**エントロピーには
  混ぜない**(粒の出自は崩壊イベントのみ)。ホストは `(boot_id, seq)` で
  重複を排除するため、ESP32 の再起動と再送を区別できる。
  `esp_random()` を使わないのは、WiFi/BT を持たないこのファームでは一意性が
  保証されず、boot_id が衝突するとホストが新鮮な粒を既出として捨てるため。
- `E` 行は自己完結させる(`boot_id` を含める)。ホストが途中から接続して
  `V` 行を見逃しても、正しく重複排除できるようにするため。
- `seq` は boot ごとに 0 から始まる通し番号。
- `events` はそのブロックに寄与した崩壊イベント数。ホストのエントロピー
  計上の根拠になる。
- ブートローダの ROM メッセージが混ざるので、ホストは未知の行を黙って捨てる。

## 規律 (変更禁止)

- **疑似乱数で埋めない**: イベントが少なくても、乱数を捏造して出さない。
  溜まった分だけ出す。管が細い日は細いまま。
- **二重投入禁止**: 全ブロックに `(boot_id, seq)` が付く。ホストがこれで
  重複を排除し、kuda への POST は 200 を確認してからキューを消す。
- **バッファ満杯時**: 未送出キューが上限(4KiB)に達したら、新規蓄積を
  停止して `W` 行で警告。古い粒の破棄も新しい粒の上書きもしない。

## 可観測性 (シリアル 115200)

10秒ごとに `S` 行を1本。人が読める簡潔さを保つ。イベント当日にプロジェクタへ
映すのは tubed 側の出力(`docs/tubed-spec.md`)を想定する。

## テストモード

`config.h` の `TEST_MODE=1` で、GPIO割り込みの代わりに擬似ポアソン過程
(平均 `TEST_CPM`、乱数は `esp_random()` ※テスト専用)でパイプラインを駆動する。
ガイガー未接続でも配線以外の全経路を検証できる。TEST_MODE 時は `E` 行の
出自が `test` になり、本番の `geiger#` と混ざらない。

## 受け入れ条件

1. TEST_MODE で `E` 行が出力され、tubed 経由で kuda の `pool_remaining` が増える
2. 実パルス(タクトスイッチ手動でも可)で `S` 行のCPMが動き、LEDが点滅する
3. USB 抜き差し・tubed 再起動で二重投入が起きない
4. 電源断→再起動で正常に再開する(蓄積分の消失は許容)
5. 秘密情報がファーム・シリアル・リポジトリに存在しない

## 非目標

- OTA更新、Web UI、LCD表示 (第二弾イベントの領分)
- ネットワーク送信・カーネルへの注入 (どちらも tubed の領分)
- 線量計算 (µSv/h換算はこのプロジェクトの目的ではない)
